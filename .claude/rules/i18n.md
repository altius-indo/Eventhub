# Languages (English + Hindi)

- No hard-coded user-facing text. Add keys to `src/i18n/messages/en.ts` and the same keys to `hi.ts`
  (it's typed as `Messages`, so missing keys fail typecheck; `tests/i18n.test.ts` checks placeholders).
- Use placeholders, not concatenation: `t("guests.summary", { guests, households })`.
- Avoid English plural traps ("1 rows"): prefer label-style copy, e.g. "Rows skipped: {count}".
- Hindi: natural, warm, everyday Hindi in Devanagari (not literal translation, not Sanskritised).
  Keep brand/tech words people use as-is (RSVP, WhatsApp, Excel, OTP). Respectful forms (आप).
- Dynamic keys (audit actions, error codes) go through `translateDynamic(locale, key, vars)`.
- Format dates/times/money with `formatDay`, `formatTime`, `formatDateTime`, `formatInr` (Indian grouping).
- Client components receive already-translated strings as props; don't import catalogues on the client.
- Guest-facing pages pick the language from `?lang`, then cookie, then the family's `locale`.
